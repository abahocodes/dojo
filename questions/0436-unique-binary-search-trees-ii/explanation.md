# Approach: choose the root, recurse on both sides

In a BST on the values `lo..hi`, choosing the root `v` forces the values below
`v` into the left subtree and those above it into the right. The left subtree
can be any BST on `lo..v-1`, the right any BST on `v+1..hi`, and every pairing
gives a different tree. So the trees on a range are generated by trying each
root and taking the cross product of the two sides' trees.

An empty range contributes exactly one tree, the empty one (`None`); that makes
the cross product work at the edges. Results for a range are memoized, so the
same subtrees are shared between several parents. That is fine because nothing
modifies the trees afterwards.

```python
def generate_trees(n):
    memo = {}

    def build(lo, hi):
        if lo > hi:
            return [None]
        if (lo, hi) in memo:
            return memo[(lo, hi)]
        trees = []
        for v in range(lo, hi + 1):
            for left in build(lo, v - 1):
                for right in build(v + 1, hi):
                    trees.append(TreeNode(v, left, right))
        memo[(lo, hi)] = trees
        return trees

    return build(1, n)
```

The number of trees is the `n`-th Catalan number (1, 2, 5, 14, 42, 132, 429,
1430 for `n = 1..8`).

## Complexity

- Time: O(C(n) * n) roughly: one new root node for each tree on each range,
  where C(n) is the n-th Catalan number, about 4^n / n^1.5.
- Space: the output dominates; memoized ranges share subtrees, so new nodes
  are created only for roots.

## Pitfalls

- Returning `[]` for an empty range wipes out every combination that uses it;
  it must be `[None]`.
- Reusing one root node object across different trees (mutating its children)
  corrupts earlier results. Create a fresh root for each pair.
- Sharing *subtrees* is safe here only because the trees are read-only after
  construction. If a caller later mutates one tree, the others change too.
